# 西安铁一中校园娱乐墙

这是一个独立于 `tyz.l.cd` 原页面 UI 的校园墙，使用苹果风格的半透明磨砂界面，保留原站公开内容形态：搜索、发帖、回复、点赞、举报、删除、公告和管理员入口。

## 本地运行

需要 Node.js `>=22.13.0`。

```bash
npm install
npm run dev
```

生产构建：

```bash
npm run build
npm run start
```

Sites 发布构建使用：

```bash
npx vinext build
```

## 持久化与媒体

主数据和图片/视频都使用 S3 兼容接口写入 COS。默认配置已经指向：

- Endpoint：`https://s3.hi168.com`
- Bucket：`hi168-hn5v4cadp72-j4lk05u0-s`

Access Key、Secret Key、管理员密码和会话签名密钥只从环境变量读取，不能写进源码或提交到 GitHub。完整变量名见 [.env.example](./.env.example)。`COS_REGION` 默认是 `us-east-1`，如果 COS 控制台为该桶指定了其他签名区域，请按控制台值修改。

图片和视频采用短时预签名 URL 直传 COS，不经过 EdgeOne 函数中转。COS 桶需要允许本站域名进行 `PUT`、`GET`、`HEAD` 跨域访问；正式域名和本地开发域名都应加入 CORS 白名单。

举报会额外写入 `flzx/reports/`，包含举报原因、帖子编号、时间和处理状态；访客标识只以哈希形式保存，用于防止同一浏览器重复举报。管理员登录后在 `/admin` 的“举报投诉”面板处理记录。旧墙迁移过来的 `report_count` 没有逐条原因，只会显示为历史举报汇总。

主页的消息通知需要用户点击“同意并开启”完成浏览器授权。授权成功后同一站点同一浏览器不会再次申请；通知目前在页面保持打开时轮询新动态，浏览器完全关闭时不会产生后台推送。

## 管理员与迁移

配置 `ADMIN_PASSWORD` 和 `ADMIN_SESSION_SECRET` 后访问 `/admin`。管理员接口不受维护模式拦截，其他公开 API 在迁移期间会返回：

```text
服务器正在重启更新
```

迁移流程：

1. 默认迁移源是 `https://tyz.l.cd` 的公开 API；如果要迁移旧服务器的 COS，则把 `MIGRATION_SOURCE_TYPE` 设为 `s3`，并配置完整的 `MIGRATION_SOURCE_*`。
2. 登录 `/admin`，填写源前缀和目标前缀，点击“开始迁移”。
3. 反复点击“继续迁移一批”，观察已复制、跳过和失败数量。
4. 确认错误为零或已处理后点击“完成并恢复服务”。

API 迁移会把旧墙的帖子、回复、点赞数、举报数和公告写入当前数据结构；S3 迁移时，目标前缀留空会保持源对象路径不变，填写前缀会把源对象复制到该前缀下。S3 迁移采用“目标已有同名对象则跳过”的方式，可安全重复执行批次。中止迁移会关闭维护模式，但不会删除已复制对象。

旧源的访问密钥只应配置在 EdgeOne 的环境变量中，不要填进前端页面。部署到 EdgeOne Pages 时，把 `.env.example` 中的变量分别添加到项目的运行时环境变量，并重新部署使其生效。

## 安全提醒

如果 COS Secret Key 曾经出现在聊天记录、截图或日志中，应立即在 COS 控制台撤销并重新生成，再只把新密钥写入 EdgeOne 的加密环境变量。仓库中不包含任何真实密钥。
